# Радар возможностей — порядок отчётности (утверждаемая редакция 22.10.2026)

## Назначение
Миссия — найти пользователю законные способы получить **дополнительную чистую прибыль ориентировочно +50 000 ₽/месяц**, допускаются несколько независимых источников. Пользователь **не санкционировал самостоятельное создание новых продуктов**: по умолчанию только исследование, фактическая проверка, сравнение, предложение к обсуждению. Никаких MVP, сайтов, агентов, запусков trial, расходов, регистраций или контактов без отдельного согласования конкретного действия.

## Периодичность и каналы
- **Среда, 06:30 МСК** — «РАЗВЕДКА / НОВЫЕ ВОЗМОЖНОСТИ»: сканирование всех трёх контуров с широким охватом и антизацикливанием; публикация 0–5 существенных активов и 0–3 действительно новых механизмов заработка **только при основаниях**.
- **Суббота, 06:30 МСК** — «ПРОВЕРКА / РЕШЕНИЯ»: перепроверка сильных кандидатов и открытых вопросов, свежие источники и новые классы, экономики, контраргументы, решение по каждой старой гипотезе; 0–3 достойных новых предложения, если появились. Не повторять среду без изменений.
- **Первая суббота месяца** — в составе обычного субботнего выпуска краткий «МЕСЯЦ / ПРОГРЕСС ДОХОДА»: новые независимые находки, снятые гипотезы, доказанные реальные платежи (если есть), потраченное время и подтверждённые денежные расходы, результаты согласованных тестов, прогресс к 50 000 ₽ чистыми. **Не создавать отдельную задачу.**
- Не обещать дополнительных фоновых публикаций между запусками без отдельного расписания/автоматизации. Вручную запрошенный выпуск можно делать по просьбе пользователя.
- **Краткий выпуск** в чате исходной автоматизации: результат сразу в первых строках, 1–3 лучших кандидата, их потенциальный плательщик, сумма/доход с явным источником, риски, следующее решение и 1 ссылка на полный выпуск. При нуле — честно ноль, но описать важные причины отказа.
- **Полный выпуск** на неизменяемом корневом GitHub Pages: https://vldik-hue.github.io/opportunity-radar/ ; новый раздел сверху, старые выпуски остаются в том же `index.html`. Не создавать новый сайт или публичный сервис.
- **Накопительная база** Google Sheets «Радар возможностей — база знаний»: https://docs.google.com/spreadsheets/d/1XpBalq3jTwr1gFLwmY1s3v_hmxA4MBtH0y2UqsJfevU/edit ; прежние семь вкладок сохраняются. Записывать только факты/гипотезы с явным статусом, обновлять старые карточки при повторе, журналировать проверку, читать обратно. «Выпуски» пополнять только после реального обновления сайта и проверки.

## Три контура одновременно
I. Недооценённые активы: покупка / договорное управление / совместная монетизация. Права, трафик и реальные денежные потоки обязательны к проверке.
II. Способы заработка без покупки активов: услуги, посредничество, B2B-запросы, узкие рыночные разрывы и иные механизмы.
III. Создание собственных продуктов (цифровых и физических): **только как идея для оценки**, не разработка по собственной инициативе.
Не превращать примеры пользователя в обязательную тему. Искать другие отрасли. Не смешивать с отдельно управляемой «Подработкой 17+», «Радаром спроса — Балашиха» или инвестиционным помощником.

## Обязательная карточка кандидата
1. **ID, дата, контур, класс и статус:** МИКРОТЕСТ ДЛЯ ОБСУЖДЕНИЯ / НУЖНЫ ДОКАЗАТЕЛЬСТВА / НАБЛЮДАТЬ / ОТКЛОНИТЬ. Микротест не санкционируется автоматически.
2. **Что продаётся или создаётся**, конечный измеримый результат; **кто платит именно пользователю** и почему.
3. **Прямой первоисточник** + дата публикации и дата проверки; отделить «факт источника» от слов продавца/прогноза и от факта собственной оплаты.
4. **Экономика:** потенциальная разовая выручка, расходы, трудозатраты, налоги/комиссии, чистая прибыль в трёх сценариях (при доказанных вводных); неизвестное не заполнять придуманными числами. Заказной бюджет — не вознаграждение посредника.
5. **Конкуренция, право/доступ, главный контраргумент, стоп-условие**.
6. **Дешёвый эксперимент для согласования**: что проверить без расходов, что считать успехом, что — отказом.
7. **Изменение с прошлого выпуска** (или чётко обозначить новую находку), без дублей.

## Стандарт содержания
В начале отчёта обязательно сообщить: дату и тип выпуска; число *новых подтверждённых платежей пользователя* (обычно 0), число проверенных новых предложений, число сильных кандидатов. Запрещены формулировки «заработаем 50 000» по модельным подсчётам без клиентов.
Структура: «Короткий итог» → «Лучшие кандидаты» → «Отклонено/изменилось» → «Что проверить дальше» → «Развитие метода и антидубли» → «Что нужно согласовать с пользователем».
В конце: состояние записи в Sheets, GitHub commit SHA, подтверждение/сбой проверки публичной страницы, точный URL. Если опубликован GitHub commit, но Pages не проверен — не писать «опубликовано и доступно».

## Протокол публикации
Сначала публичные источники и сравнение с историей, затем журнал Sheets, затем GitHub fetch current index.html SHA → полное точечное обновление index.html с сохранением всех прежних разделов → повторный fetch → внешняя проверка Pages → **только после** запись в «Выпуски» с честным статусом. Пользователь получает краткую выжимку в чате задачи в рамках планового запуска; доставка push зависит от настроек продукта.
